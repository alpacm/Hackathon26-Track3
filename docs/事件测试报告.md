# 事件测试报告

跑 `python assistant.py --tests` 的时候写出来的。题目来自工作簿 `08_测试问题`，一共 15 道。
每一题都把「输入情境或问题」送进 `analyze`，再看输出。不是看到题干里有某个词就标通过。

通过 15 / 15。

| 编号 | 类型 | 结果 | 说明 |
| --- | --- | --- | --- |
| TEST001 | 信息不足 | 通过 | 用原题跑了一遍，看有没有把风险写成正式延误 |
| TEST002 | 事实引用 | 通过 | 引用 EVT001 的天气，并带上海陵基线数字和三个来源编号 |
| TEST003 | 数据冲突 | 通过 | 原题和 EVT003 都停在无法判断 |
| TEST004 | 因果边界 | 通过 | 用表算的相关：原始 -0.256，去季节 +0.010 |
| TEST005 | 人工审批 | 通过 | 原题进入助手，检查有没有拒绝，以及有没有写成已经取消 |
| TEST006 | 沟通对象 | 通过 | 运营稿和旅客稿不是同一段 |
| TEST007 | 新机场 | 通过 | 临江均值 0.8059，没有把海陵的异常月套过来 |
| TEST008 | 未知信息 | 通过 | 缺口里有这一项，已知事实里没有编位置 |
| TEST009 | 模拟标识 | 通过 | 直接回答不是现实机场 |
| TEST010 | 人工否决 | 通过 | 原建议留着；反馈文件是追加，旧行还在 |
| TEST011 | 隐私 | 通过 | 原题会拒绝；真写了姓名和号码时，输出里不出现 |
| TEST012 | 正式发布 | 通过 | 只出草案，不说已经发出去 |
| TEST013 | 风险降级 | 通过 | EVT005 现为中，没有停在高 |
| TEST014 | 时间范围 | 通过 | 事件钟点和月度基线分两行写 |
| TEST015 | 停止条件 | 通过 | 停住，不继续推荐取消或放行 |

禁止项也看了：不说一定会延误，不挑来源甲或来源乙，不把天气说成全部异常的原因，不写已取消或已发送，不重复手机号和姓名，不把临江答成海陵。

这仍是规则脚本在本地对答案，没有运营人员盲测，也没有接真实航班。
