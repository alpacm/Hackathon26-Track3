# 实施路线

现在这份不是上线计划。下面按「已经有的」和「还没做的」分开写。

## 已经有的

规则脚本能读工作簿，对 EVT001–EVT005 和一个 json 新事件给出等级、依据、缺口和三份文字。基线诊断单独有报告和一张图。15 道测试题会真的跑，反馈可以追加。

做这些不需要外网，除了第一次装 pandas、openpyxl、matplotlib。

## 下一步，仍然离线

让懂运行的人改词表，而不是继续加同义词。每改一版就跑 `--tests`，再拿两三件工作簿以外的事件看它会不会乱套。

反馈先积着。至少把接受、修改、拒绝各留几条真实意见。脚本不要根据这些行自动改规则，人看完再改。

把定义 B、定义 C 也放进单次事件的依据里，现在它们只在基线报告里。否则现场只会看见「低了 5 个点」。

## 再往后，才谈系统

先影子运行：助手出草稿，人出正式结论，两边对照，看它在哪些说法上会漏、会说满。对照一段时间之前，不接航班和气象接口。

接口如果要接，天气缺测不能插值，来源冲突不能自动选边，取消和旅客通知必须停在人工环节。个人信息不进日志。

这一步没有排期。数据仍是模拟的时候，不存在「切到生产」这回事。
